## 何が変わったかを見る

作業前に状態を確認し、コミット前に差分を読みます。少ない手間で、変更の範囲を把握できます。

```bash
git status --short
git diff
git diff --staged
```

順に、作業ツリーの状態、まだステージしていない変更、次のコミットに入る変更を確認します。

## 一つの目的にまとめる

ナビゲーションのリンク修正を終えて確認し、見た目の変更は次のコミットにまとめます。小さな変更はレビューしやすく、あとから問題を探す際にも役立ちます。

## 結果を説明する

「モバイルメニュー展開時の文字コントラストを修正」のように、何が改善したかを書きます。本文には発生条件や確認方法を添えると、背景が伝わります。

## 未来の自分に手がかりを残す

わかりやすい履歴は、短い開発日誌にもなります。数か月後でも、その判断をした理由を理解する助けになります。
